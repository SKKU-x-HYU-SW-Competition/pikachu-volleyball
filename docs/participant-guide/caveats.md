# 자주 걸리는 함정

봇 개발 중 여러분이 헷갈리기 쉬운 것들을 몰아서 정리했습니다. 붙여봤는데
이상하다 싶으면 이 페이지부터 훑어보세요.

## 좌표계

### Y축이 아래로 증가합니다

"공이 최고점에 있을 때 y가 크겠지" 같은 직관은 **틀립니다.**

- 캐릭터가 땅에 서 있음: `y = 244`
- 공이 공중에 뜸: `y`가 **작아짐**
- 공이 최고점: `y`가 가장 작음
- 공이 낙하 중: `yVelocity > 0` (양수 = 아래 방향)

### 코트가 좌우로 나뉜다

`x = 216`이 네트 위치입니다. LEFT 봇은 `x ∈ (0, 216)`, RIGHT 봇은
`x ∈ (216, 432)`에서만 움직일 수 있습니다.

## `hit`, `x`, `y`의 오해하기 쉬운 관계

### 파워히트 방향은 `x`가 아니라 "네트 위치"로 결정

파워히트 순간 `x = 1`을 넣으면 공이 오른쪽으로 갈 것 같지만 **아닙니다.**
엔진은:

- 공이 네트의 왼쪽에 있으면 → 오른쪽 코트로 넘김
- 공이 네트의 오른쪽에 있으면 → 왼쪽 코트로 넘김

봇의 `x` 부호는 이것과 무관하게, 단지 **파워히트 속도를 두 배로**만 만듭니다.
0이면 기본 속도, 아무 방향이든 nonzero면 2배 속도.

### 강스매시(`y=1`)는 자기 코트에 자기 스매시 위험

파워히트 순간 `y = 1`을 넣으면 공이 **급격히 아래로** 꽂힙니다. 내가 네트에서
멀면 공이 네트를 넘기 전에 내 코트 바닥에 박힙니다. 자책골 각.

→ 네트에서 가까울 때(약 80픽셀 안)만 `y = 1`, 멀면 `y = -1`로 아치.

### 점프는 별도 필드가 없다

`y = -1`을 **땅에 있는 상태(`state === 0`)** 에서 보내면 그게 점프입니다.
점프 중(`state === 1`)에 `y = -1`을 보내는 건 스매시 각도만 결정할 뿐 다시
점프시키지 않습니다.

### 다이빙 = 지상 + 이동 + `hit`

`state === 0`(땅), `x ≠ 0`(이동 중), `hit = 1` 세 조건이 다 맞아야 다이빙.
`hit = 1`이라고 무조건 파워히트가 나가는 게 아닙니다.

## 반응 지연 (~1 tick)

여러분이 이번 틱에 낸 결정은 **다음 틱**에 반영됩니다. 브라우저 구조상 어쩔
수 없는 지연이라 없앨 수 없습니다.

- 나쁜 소식: 반응이 실제로 1 tick(~120ms) 늦음
- 좋은 소식: 상대도 똑같이 겪음. 공평함
- 실전 팁: 낙하지점을 향해 걸어갈 때 `Math.abs(dx) > 8` 같은 데드밴드를 두면
  이 지연 때문에 발생하는 "왔다갔다" 진동이 줄어듭니다

## 봇 코드 실행 모델

### 파일은 매치당 딱 한 번 실행됨

파일 최상위의 `var x = ...`, `def foo(): ...` 같은 것들은 **첫 tick 이전에 한 번**
실행됩니다. 그 결과로 만들어진 `decide` 함수만 이후 매 tick 호출됩니다.

즉, `decide` 밖에 `console.log("started")`를 두면 매 tick 찍히는 게 아니라
매치당 한 번만 찍힙니다.

### 전역 변수는 tick 사이에 유지

```js
var tickCounter = 0;

function decide(s) {
  tickCounter++;   // 매 tick 1씩 증가
  // ...
}
```

이걸로 "직전 공 위치를 기억", "최근 상대 패턴 카운트" 같은 걸 할 수 있습니다.

### 다만 강제 재시작 시엔 리셋됨

봇이 15 tick 연속 타임아웃하면 워커가 강제 재시작되면서 파일이 다시 로드됩니다.
쌓아둔 전역 상태는 다 날아갑니다. **정말 중요한 상태라면** 무거운 연산을
피해서 애초에 재시작이 안 일어나게 하는 게 최선입니다.

### LEFT와 RIGHT가 같은 봇을 쓰면 각자 독립적으로 로드됨

같은 파일이 양쪽에 배치돼도 각자 다른 Worker에서 실행되므로, 전역 변수는
공유되지 않습니다. 서로 못 봅니다.

## 스냅샷 필드의 함정

### `expectedLandingPointX`는 "지금 이 순간의 예상"

공이 다시 부딪히거나(플레이어·네트) 튕기면 다음 tick에 값이 확 바뀝니다.
지난 값 캐시해서 쓰지 말고 매 tick 새로 읽으세요.

### `self.state`가 0/1 아니면 대부분 조작 무시됨

- 스매시 발동 중(`state === 2`), 다이빙(`3`), 누움(`4`)에는 봇이 뭘 보내든
  캐릭터는 그 애니메이션이 끝날 때까지 자기 갈 길 갑니다
- 봇 로직에서 이 상태들을 특별히 조작할 필요는 없지만, "왜 갑자기 반응이
  씹혔지?" 싶을 땐 `self.state`를 로그해보세요

### `meta.score`는 자기 관점 기준

`meta.score.self`는 항상 "내" 점수, `meta.score.opp`는 항상 "상대" 점수입니다.
LEFT면 실제 왼쪽 점수가 self, RIGHT면 실제 오른쪽 점수가 self.

## `console.log` / `print`의 함정

### 매 tick 로그 = 브라우저 폭발

25 FPS × 여러 tick × 랠리 몇 번 → 순식간에 콘솔이 수천 줄이 되면서 브라우저가
느려집니다. 반드시 카운터로 걸러서:

```js
if (tickCounter % 100 === 0) console.log(...);
```

### 로그 위치

- JS: `console.log`, `console.warn`, `console.error` → 브라우저 개발자 도구
  Console 탭
- Python: `print(...)` → 같은 Console 탭

## Python 특유

- **첫 Apply 후 몇 초 로딩** 있음 (Pyodide + numpy). 두 번째부터는 즉시
- `snapshot`은 dict라 `s.ball.x`가 아니라 `s['ball']['x']`
- `numpy`만 사용 가능. `scipy`/`pandas`/`sklearn` 등은 초기화 에러
- 반환값도 반드시 dict (tuple, list, dataclass는 무입력 처리됨)

## 안전한 개발 루틴

1. 코드 수정 → 저장
2. dev 서버가 자동 재빌드 (터미널 로그에서 "compiled" 확인)
3. Bot Setup을 다시 열지 말고 **브라우저에서 Apply만 다시 클릭** — 그러면 새
   코드로 매치 재시작
4. 개발자 도구(F12) Console 탭 열어두고 예외 메시지 확인
5. 이상하면 원인이 잡힐 때까지 Minimal에 조금씩 로직을 얹어가며 이등분 탐색
