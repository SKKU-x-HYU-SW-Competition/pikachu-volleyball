1. 최소한의 stub(임시 기본값)으로 막아서 작업을 계속하고,
2. 아래에 새 항목을 추가하고 (`질문` / `왜 막혔는지` / `임시 처리(stub)` / `담당`),
3. 실제로 결정되면 `상태`를 `RESOLVED`로 바꾸고 `결정 내용`, `결정일`을 채우세요 (행을 지우지 마세요 — 왜 그렇게 정했는지가 나중에 중요해집니다).

이 문서에 있는 항목은 **개인이 임의로 RESOLVED 처리하지 말고**, 정기 회의에서 결정한 뒤 반영하세요.

### D-003. 에이전트 코드 실행 방식 (샌드박싱 필요 여부)

- **왜 막혔는지**: 참가자가 짜온 JS 코드를 브라우저에서 동적으로 로드해야 함 (동적 import? `eval`?
  `Function` 생성자?). 대회 현장 PC에서 신뢰할 수 없는 코드를 돌리는 것이므로 최소한의 격리가

  악용 우려 낮음/높음 판단 필요).
