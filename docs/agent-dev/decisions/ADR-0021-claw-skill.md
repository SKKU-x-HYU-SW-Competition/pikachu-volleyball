## 배경

[ADR-0020(게이지)](ADR-0020-gauge-system.md)에서 스킬 자원만 먼저 구현하고 "스킬 효과가 무엇인가 /
소모량 / 봇 프로토콜 확장 / 사람 발동키"는 OPEN으로 남겼다. 이 ADR은 그중 **첫 번째 스킬**을
팀장 제안대로 확정한다.

> 이전에 검토하던 「백만볼트」(땅과 평행하게 번개 발사 → 점프로 회피)는 **폐기됐다**(팀장 결정,
> 2026-08-11). 해당 ADR 초안은 등재 전 삭제했으므로 번호를 소모하지 않았다.

## 1. 스킬 정의 (팀장 제안 — 콘셉트 확정)

**「claw」**

| 항목 | 내용 |
|---|---|
| 발동 조건 | 게이지 **50 소모** (변수) |
| 효과 | 시전자가 **특정 x좌표 범위**(변수)에 발톱 생성을 예약 |
| 예고 | 범위가 정해지면 **1초 동안** 그 범위를 알리는 시각 효과 표시 |
| 발동 | 1초 뒤 그 범위에 발톱 생성. 그 순간 **상대 히트박스가 범위에 겹치면 1초 기절**(이동 불가) |
| 공중 피격 | 기절과 동시에 **즉시 땅으로 순간이동** |
| 파훼법 | 예고 1초 안에 범위 밖으로 이동 |

## 2. 기절을 엔진 수정 없이 구현할 수 있는 이유 (핵심 근거)

원본 엔진에는 이미 "움직일 수 없는 상태"가 있다 — 다이빙 후 **누움 상태(`state === 4`)**다
([`physics.js:507-512`](../../../src/resources/js/physics.js#L507-L512)):

```js
// if player is lying down.. don't move
if (player.state === 4) {
  player.lyingDownDurationLeft += -1;
  if (player.lyingDownDurationLeft < -1) {
    player.state = 0;
  }
  return;
}
```

1. **이동 입력이 전부 무시된다** — x 이동/점프/파워히트 코드보다 먼저 `return`한다.
2. **기본 탑재 AI에게도 걸린다** — `letComputerDecideUserInput()`이 위에서 호출되지만 AI가 무슨
   입력을 만들든 여기서 잘리므로, 키보드·봇·기본 AI 세 종류 모두에게 동일하게 적용된다.
3. **지속시간과 자동 복귀가 이미 구현되어 있다** — `lyingDownDurationLeft = N`이면 N+2 프레임 뒤
   자동으로 `state = 0`으로 돌아온다.

따라서 기절은 엔진 밖에서 `player.state = 4; player.lyingDownDurationLeft = N;`을 쓰는 것으로 끝난다.
ADR-0020이 `isCollisionWithBallHappened`를 밖에서 관찰한 것과 같은 계층이며 `physics.js`는 무수정이다
→ [05-skill-extension-guide.md](../../architecture/05-skill-extension-guide.md) 분류상 **Tier A**.

**공중 피격 시 순간이동이 여기서 필수인 이유**: 위 블록은 중력 처리보다 먼저 `return`하므로, 공중에
있는 플레이어를 그냥 `state = 4`로 만들면 **허공에 떠서 멈춘다**. 그래서 기절을 적용할 때
`y = PLAYER_TOUCHING_GROUND_Y_COORD`, `yVelocity = 0`을 함께 쓴다 — 팀장이 요구한 "즉시 땅으로
순간이동"이 곧 이 부작용의 해결책이기도 하다.

## 3. stub 상수 (회의에서 확정할 값들)

전부 `skill/claw.js` 상단 상수라 숫자만 바꾸면 된다.

| 상수 | stub 값 | 근거 / 주의 |
|---|---|---|
| `CLAW_COST` | `50` | 팀장 제안값. 게이지 최대 100 = 1터치 리턴 10회 |
| `CLAW_WIDTH` | `96` (물리 px) | 플레이어 폭(64)의 1.5배. 플레이어는 프레임당 6px 이동하므로 예고 25프레임이면 최대 150px 이동 가능 → 좁으면 회피가 너무 쉽고 넓으면 회피 불가. **실측 후 조정 1순위** |
| `CLAW_WARNING_FRAMES` | `25` | 1.00초 (25fps) |
| `CLAW_STUN_FRAMES` | `23` | 엔진이 N+2 프레임을 쓰므로 23 → 25프레임 = **1.00초** |
| `CLAW_ACTIVE_FRAMES` | `10` | 발톱 이미지를 보여주는 시간(0.4초). 판정은 생성 순간 1회뿐이며 이 값은 연출용 |
| `CLAW_HEIGHT` | `304` (물리 px = 코트 전체 높이) | **x 범위 안의 모든 y가 판정 대상**이라(팀장 확정) 그리는 기둥도 화면 전체 높이다. 판정 범위와 표시 범위가 항상 같다 |
| `CLAW_KEY_P1` / `_P2` | `'KeyC'` / `'ShiftRight'` | 현재 미사용 키. P1은 D/G/R/V/Z/F, P2는 방향키+Enter를 씀 ([`pikavolley.js:42-51`](../../../src/resources/js/pikavolley.js#L42-L51)) |

## 4. 스펙에 없어서 임시로 정한 것 (전부 회의 확정 대상)

1. **범위를 어디에 잡는가 — 확정됨** (팀장, 2026-08-11): 실제 대전 주체는 사람이 아니라 봇이므로
   **봇이 x를 직접 지정**한다(액션 필드 `skillX`, [ADR-0022](ADR-0022-bot-skill-action-field.md)).
   사람이 키보드로 테스트할 때는 좌표를 입력할 방법이 없으므로 기존 동작대로 **발동 시점 상대
   위치를 중심**으로 잡는다. 두 경로가 같은 `tryCast()`를 쓰고 조준값만 다르다.
2. **판정 축 — 확정됨** (팀장, 2026-08-11): x 범위 안의 **모든 y**가 판정 대상이다. 상대
   히트박스 `x ± PLAYER_HALF_LENGTH(32)`가 `[centerX - W/2, centerX + W/2]`와 겹치면, 그 순간
   상대가 공중에 있든 땅에 있든 피격이다. 즉 **점프로는 피할 수 없고** 좌우 이동만이 회피 수단이다
   ("공중에서 맞으면 땅으로 순간이동"이라는 스펙 자체가 공중 피격을 전제한다). 그리는 기둥도 같은
   이유로 화면 전체 높이다.
3. **발동 제한** — 예고 중이거나 이미 기절/승패 모션(`state` 4·5·6) 중이면 재발동 불가. 플레이어당
   동시에 예약 1개.
4. **랠리 경계** — `round` 상태를 벗어나면 예약된 발톱과 표시를 모두 취소한다 (게이지 트래커와 같은
   패턴). 랠리가 끝난 뒤 발톱이 터지는 것을 막기 위함이며, **소모한 게이지는 환불하지 않는다**.
5. **발동 입력** — 봇은 액션 필드 `skillX`로([ADR-0022](ADR-0022-bot-skill-action-field.md)),
   사람은 발동 키로 쓴다. 키 입력은 `PikaKeyboard`를 건드리지 않고 별도 `keydown` 리스너로 받는다 —
   스킬 입력은 엔진의 3필드 프로토콜 밖에 있고, 키보드 클래스를 확장하면 봇/기본 AI 슬롯까지 의미가
   번지기 때문이다. **기본 탑재 AI는 스킬을 쓰지 못한다**(맞기만 한다) — 밸런스 테스트 시 감안할 것.
6. **임시 에셋** — 예고/발톱 이미지는 단색 PNG(384×1216 = 물리 96×304 × RATIO 4)를
   `src/resources/assets/images/skill/`에 넣었다. 둘 다 **반투명**이다: 불투명하면 발톱이 피격자를
   가려서 "제대로 땅에 떨어지는지"를 확인할 수 없다(팀장 요청). 실제 아트로 교체할 때 파일만
   갈아끼우면 되고, 그리는 크기는 `CLAW_WIDTH`/`CLAW_HEIGHT`에서 나오므로 이미지 픽셀 크기가 달라도
   스킬 판정 범위와 어긋나지 않는다.

## 5. 아직 OPEN인 것

1. ~~**스냅샷 확장 (미착수)**~~ → **해소됨** ([ADR-0023](ADR-0023-snapshot-skill-state.md),
   CONTRACTS.md v0.7). 봇이 자기/상대 게이지와 예고 중인 발톱(`opp.claw`)을 볼 수 있게 되어
   회피가 가능해졌다. 대신 **밸런스 수치(§3 표)는 이제 봇 대전 기준으로 다시 잡아야 한다** —
   회피가 불가능하던 시절의 감각은 참고치가 아니다.
2. **스킬 개수** — [ADR-0020](ADR-0020-gauge-system.md) §4는 "소모량이 다른 스킬 여러 개 중에서
   고르는 것"이 이 시스템의 전략적 핵심이라고 못박았다. claw 하나로는 그 성질이 성립하지 않으므로
   2번째 스킬이 필요하다.
3. **게이지 바에 소모량 눈금 표시** — `CLAW_COST`가 확정되면 게이지 바에 50 지점 눈금을 그릴지.

## 6. 트레이드오프

- **`state = 4`를 밖에서 세팅하는 것은 엔진 내부 상태를 남이 건드리는 것**이다. 엔진 파일 무수정을
  유지하는 대가이며, 원본이 이 필드를 공개 필드로 두고 있어 가능하다. "다이빙 후 누움"과 "기절"이
  같은 상태값을 공유하므로, 둘을 구분해야 하는 순간(전용 스프라이트 등) Tier B로 올라간다.
- **기절 모션이 다이빙 후 누움과 동일**해서 관전자가 원인을 헷갈릴 수 있다. 발톱 연출로 보완하고,
  필요하면 Phase 4-C에서 전용 스프라이트를 넣는다.
- **슬로우모션 6프레임 동안은 물리가 안 돌지만 예고 카운트다운은 `ticker` 기준으로 함께 멈춘다**
  (게이지와 동일하게 `round` 상태에서만 관찰). 의도된 동작이다.
