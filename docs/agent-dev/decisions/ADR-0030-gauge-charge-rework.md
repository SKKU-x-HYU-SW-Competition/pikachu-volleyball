## 무엇을 바꿨나

| 항목 | 기존 (v0.7) | 시안 (v0.8) |
|---|---|---|
| 리시브 (상대 공을 처음 받음) | **+15** | **+20** |
| 자기 진영 연속 터치 | **-5** (`onExtraTouch`) | **폐지** (0) |
| 스매시 (파워히트) | 없음 | **-10** (`onSmash`, 신설) |
| 서브 (랠리 첫 접촉) | 0 | 0 (변경 없음) |

`onSmash`는 **접촉 종류와 무관하게 더해진다.** 리시브를 그대로 스매시로 넘기면
`+20 - 10 = +10`이고, 자기 진영 두 번째 터치를 스매시로 넘기면 `0 - 10 = -10`이다.
`CLAW_COST`는 50 그대로다.

## 왜

**1. 연속 터치 페널티가 중복이었다.** 자기 진영에서 공을 끌면 이미
[`rules/touchLimit.js`](../../src/resources/js/rules/touchLimit.js)의 5회 제한이 실점으로 벌한다.
게이지까지 깎는 건 같은 행동을 두 번 벌하는 것이고, 실제로 그 -5가 플레이를 바꾼다는 계측도 없다.

**2. 게이지를 "선택"으로 만든다.** 기존 규칙에서 게이지는 랠리를 이어가면 저절로 차는
**부산물**이었다. 스매시에 비용을 붙이면 *어떻게* 받아넘길지가 자원 관리와 엮인다 — 매번
강하게 때리는 쪽은 스킬을 못 모으고, 살살 넘겨 버티는 쪽이 발톱을 먼저 쥔다. 스매시가 게임에서
가장 강한 리턴이므로 공짜가 아니게 하는 쪽이 자연스럽다.

**3. 리시브 +20은 그 상쇄분이다.** 스매시 -10이 붙으면 실질 충전량이 떨어지므로 리시브를
15 → 20으로 올렸다. **한 번 발동에 필요한 리시브가 (스매시를 섞지 않으면) 2.5회**로,
[ADR-0025](ADR-0025-gauge-cost-vs-charge-rate.md)가 지적한 "90초 대전에 스킬이 0~1번"보다 빠르다.
다만 **이 숫자들은 전부 계측 전 임의값이다** — 아래 §미결 참고.

## 구현

`skill/gauge.js` 안에서 끝난다. 엔진 파일은 건드리지 않았다(Tier A 유지).

스매시 판정은 엔진이 이미 공에 남기는 플래그를 읽는다:

```js
// physics.js:708-727 -- 충돌 프레임의 playerState === 2일 때만 true
const isSmash = pikaVolley.physics.ball.isPowerHit === true;
```

`ball.isPowerHit`은 **충돌 처리 안에서만** 쓰이고(그 외에는 어디서도 대입되지 않는다) 매 충돌마다
true/false로 덮어쓰인다. `observe()`는 접촉의 false→true 전이 시점에만 이 값을 읽으므로, 그 값은
방금 그 접촉을 가리킨다.

## 봇 프로토콜에 미치는 영향 (하위 호환 깨짐)

`config.gauge`에서 **`onExtraTouch`가 사라지고 `onSmash`가 생겼다.** [ADR-0023](ADR-0023-snapshot-skill-state.md)
원칙대로 튜닝 상수는 스냅샷으로 나가므로 이건 **계약 변경이고 CONTRACTS를 v0.8로 올렸다.**

- `config.gauge.onExtraTouch`를 읽던 봇은 이제 `undefined`를 본다. **에러가 나지 않고 조용히
  틀린 판단을 한다** — ADR-0023 §3이 상수를 노출한 이유가 정확히 이것인데, 이번엔 필드가 사라진
  경우라 노출만으로는 못 막는다.
- 저장소 안에서 이 필드를 읽던 곳은 계약 검사 봇(`skill_contract_check_bot.js`) 하나였고 같이
  고쳤다. 예제 봇들(`Example_v1.*`, `ClawLanding_v1.js`)은 `onReceive`/`max`만 읽어 영향 없다.
- **참가자에게 이미 배포된 봇이 있다면 안내가 필요하다.** 현재는 배포 전이라 문제가 없다.

## 미결 (회의 안건)

1. **수치가 전부 계측 전 임의값이다.** `+20 / 0 / -10`은 팀장 지시값이고, 이게 맞는지는 봇 대전
   계측으로 확인해야 한다. [ADR-0025](ADR-0025-gauge-cost-vs-charge-rate.md)가 같은 이유로
   PARTIAL이다.
2. **스매시가 리시브를 상쇄하는 정도.** 리시브+스매시가 +10이라 "강하게만 치는 봇"도 결국은
   찬다(느릴 뿐). 스매시를 아예 순손실(-20 이상)로 만들어 확실한 선택지로 만들지, 지금처럼
   완만한 기울기로 둘지.
3. **서브 스매시.** 서브(첫 접촉)를 점프 스매시로 넣으면 `0 - 10 = -10`으로 **마이너스에서
   시작한다.** 게이지는 0에서 클램프되므로 실질 손해는 없지만 의도한 규칙인지 확인이 필요하다.
4. **연속 터치 0이 랠리를 늘리는가.** 페널티를 없앴으니 자기 진영에서 세팅해 때리는 플레이가
   늘어날 수 있다. 5회 제한 안에서 벌어지는 일이라 위험하진 않지만
   [ADR-0026](ADR-0026-touch-limit-vs-smash-logic.md)과 같이 볼 사안이다.
5. **`develop-skill`로 가져갈지.** 이 브랜치는 시안용이다. 채택되면 `develop-skill`로,
   폐기되면 브랜치째 버린다.

## 검증 (구현 시점)

- `npm run verify` 통과
- 실제 봇 대전에서 규칙이 의도대로 도는지 — 리시브 +20, 연속 터치 0, 스매시 -10이
  **접촉 단위로** 관측되는지 계측 필요 (§미결 1과 함께)
