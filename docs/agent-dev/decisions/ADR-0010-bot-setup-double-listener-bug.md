# ADR-0010 — Bot Setup 패널에서 "적용"해도 봇 코드가 빈 채로 로드되는 버그

| | |
|---|---|
| 상태 | RESOLVED |
| 결정일 | 2026-07-19 |
| 결정자 | Claude Code (구현 중 발견 및 수정) |
| 반영 | [`bot/testSetup.js`](../../../src/resources/js/bot/testSetup.js) |

## 배경 (왜 막혔는지, 구현 중 발견)

Phase 2(`testSetup.js`) 구현 후 Playwright로 검증하던 중, 오른쪽 진영을 "봇 코드"로 설정하고
"적용"을 눌러도 간헐적으로 `에러: undefined` 상태가 뜨고 봇이 전혀 움직이지 않는 현상을 발견.
Worker를 직접 계측해보니 **매번 Worker가 두 번 생성**되고 있었음 — 첫 번째는 정상(붙여넣은 봇 코드
2174자), 두 번째는 빈 문자열(0자)로 초기화되어 `decide` 함수를 못 찾고 실패.

### 근본 원인

`setUpBotTestUI`가 페이지 로드 시 한 번(`armApplyOnNextRound`로 "다음 라운드 시작 시 기본 설정 적용"
예약), 그리고 "적용" 클릭 시 또 한 번, 총 두 개의 "라운드 시작 대기" 리스너가 동시에 걸릴 수 있었음.
게다가 모드 선택 버튼 핸들러가 `config[side].mode = ...`로 **기존 config 객체를 직접 mutate**하고
있었는데, 페이지 로드 시 예약된 리스너가 바로 그 (아직 `source`는 비어있는) 객체를 참조하고 있었던
것 — 그래서 라운드가 시작되면 두 리스너가 각각 다른 시점의 config로 두 번 적용을 시도했고, 나중에
도는 쪽이 앞의 정상 적용을 덮어쓸 수 있었음.

## 결정

**(1)** "라운드 시작 대기" 리스너는 항상 최대 1개만 걸리도록 재구성 — 새로 걸기 전에 이전에 걸어둔
리스너를 `ticker.remove()`로 먼저 취소. **(2)** config 객체는 어디서도 직접 mutate하지 않고 항상 새
객체를 만들어 교체하도록 수정 (mutate 자체가 안전하지 않다는 걸 보여준 사례라 재발 방지 차원에서
같이 고침). Playwright로 세 가지 조합(키보드-봇, 기본AI-봇, 봇-봇)과 새로고침 후 자동 재적용까지
재검증해서 확인.
