# ADR-0003 — 봇 코드 실행 방식 (샌드박싱 필요 여부)

| | |
|---|---|
| 상태 | RESOLVED |
| 결정일 | 2026-07-07 |
| 결정자 | Claude Code (사용자 승인) |
| 반영 | [CONTRACTS.md](../CONTRACTS.md) §1.0/§1.3, §2 |

## 배경 (왜 막혔는지)

참가자가 짜온 JS 코드를 브라우저에서 동적으로 로드해야 함. 대회 현장 PC에서 도는 코드라 최소한의
격리가 필요한지, 대회 성격상(폐쇄망, 운영진 사전 검수) 굳이 필요 없는지 미정.

## 결정

**Web Worker + 타임아웃 + `terminate()` 후 재시작으로 확정.** 같은 스레드에서 `eval`/동적 `import`로
직접 돌리면 무한루프 하나가 게임 전체(렌더링·상대 입력 포함)를 멈춰버리고, 동기 코드는 밖에서 끊을
방법이 원천적으로 없음. Worker로 분리하면 `postMessage`로 스냅샷을 보내고
[ADR-0002](ADR-0002-timeout-and-invalid-response.md)의 타임아웃 안에 응답이 없으면 무입력 처리,
반복되면 강제 종료 후 재시작해서 나머지 경기는 영향받지 않게 할 수 있음. 이번 대회는 참가자 신원이
확인되고 운영진이 사전 검수하는 친선전이라 위협 모델상 "악성 코드 차단"보다 "현장에서 버그 하나가
시연 PC를 멈추는 것 방지"가 실질적 리스크로 판단, iframe sandbox 등 더 무거운 보안 격리는 후순위로
미룸.
