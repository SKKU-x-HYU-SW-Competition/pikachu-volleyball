# ADR-0011 — Bot Setup: 봇이 인트로/메뉴 내비게이션을 막아서 다음 경기를 시작 못 하는 버그

| | |
|---|---|
| 상태 | RESOLVED |
| 결정일 | 2026-07-24 |
| 결정자 | Claude Code (사용자 제보, 구현 중 수정) |
| 반영 | [`bot/testSetup.js`](../../../src/resources/js/bot/testSetup.js) |

## 배경 (왜 막혔는지, 사용자 제보)

좌우 진영을 둘 다 "봇 코드"로 설정하면 첫 경기는 정상적으로 시작되지만, 그 경기가 끝나고 인트로
화면으로 돌아온 뒤에는 다음 경기가 시작되지 않는 버그가 있었음.

### 근본 원인

기존 `testSetup.js`(Phase 2, [ADR-0010](ADR-0010-bot-setup-double-listener-bug.md) 수정 버전)는
"라운드가 처음 시작되는 순간 1회" `keyboardArray`를 봇/AI로 교체하는 **일회성** 로직이었음. 하지만:

- 인트로(`intro()`)와 메뉴(`menu()`) 화면은 `keyboardArray[i].powerHit`/`yDirection` 값으로
  내비게이션(스킵/1P·2P 선택)을 판단함 — 사람이 물리 키를 눌러야 하는 지점.
- 반면 물리 엔진(`physics.runEngineForNextFrame`)은 `round()` 상태에서만 호출되므로, 인트로/메뉴
  화면에서는 공/플레이어 상태가 갱신되지 않고 이전 경기 종료 시점 값에 멈춰 있음. 봇의 `decide()`는
  이 멈춰있는 스냅샷을 보고 매 틱 똑같은(대개 무의미한) 값을 낼 뿐, "여기는 메뉴 화면이니 확인 키를
  눌러야 한다"는 개념 자체가 없음.
- 한 번 `keyboardArray`가 봇으로 교체된 뒤에는 되돌리는 로직이 없었기 때문에, 경기가 끝나고
  인트로로 돌아와도 여전히 봇이 (내비게이션에 무의미한) 입력을 내고 있었고, 실제 키보드는 더 이상
  아무 역할도 하지 않았음.

## 결정

**"라운드 시작 시 1회 적용" 대신, 매 틱 게임 상태를 확인해서 계속 동기화하는 상시 워처로 변경.**
`round`/`afterEndOfRound`/`beforeStartOfNextRound`(= 한 경기 안에서의 랠리↔랠리 전환, 계속 봇 유지)
상태일 때만 설정된 봇/AI를 적용하고, 그 밖의 상태(인트로/메뉴 등, 다음 경기 시작 전)로 돌아가면
자동으로 실제 `PikaKeyboard`로 되돌려서 사람이 다음 경기를 내비게이션할 수 있게 함. 경기가 다시
시작되면 워처가 다시 감지해서 설정된 봇/AI를 재적용함 — 매 경기마다 반복.

Playwright로 검증: 봇 vs 봇으로 라운드 진입 → `restart()`로 경기 종료 상황 재현 → 인트로 화면에서
물리 키 입력(Z)으로 메뉴 진입 성공 → 다음 라운드에서 양쪽 봇 재적용까지 확인.
