## 배경 (왜 막혔는지)

참가자 봇 함수가 예산([ADR-0001](ADR-0001-tick-frame-group-size.md)) 안에 응답하지 못하거나 형식이
잘못된 값을 반환하면 어떻게 할지 안 정해짐 — 이전 입력 유지 / 무입력(0,0,0) 처리 / 해당 라운드
실격 중 선택 필요.

## 결정

**무입력(`x=0, y=0, hit=0`)으로 확정.** 기존 두 입력 소스(`PikaKeyboard`, 기본 AI인
`letComputerDecideUserInput`)가 이미 매 틱 0으로 리셋한 뒤 그 틱에 확정된 것만 채우는 방식이라
([`physics.js:804-806`](../../../src/resources/js/physics.js#L804-L806)), "이전 값 유지"는 이 엔진에
없던 세 번째 규칙을 새로 만드는 셈이 됨. 한 틱 놓치는 건 어차피 체감이 안 되고, 여러 틱을 연달아
놓치는 상황(행)에서는 "이전 입력 유지"가 오히려 의도치 않은 반복 발동(예: 타임아웃 시작 시점에
`hit=1`을 들고 있었다면 착지할 때마다 다이빙이 계속 재발동)으로 이어질 수 있어 무입력이 더 안전.
실격은 일시적 지연(GC 멈칫 등)까지 처벌하게 되어 과함 — 다만 N틱 연속 타임아웃 같은 "지속적인 행"에
대한 운영진 알림/에스컬레이션은 이번 결정 범위 밖이며, Phase 3(제출/중계) 설계 시 별도로 다룸.
