# ADR-0001 — 틱 길이 (몇 프레임 = 1 틱?)

| | |
|---|---|
| 상태 | RESOLVED |
| 결정일 | 2026-07-07 |
| 결정자 | Claude Code (사용자 승인) |
| 반영 | [CONTRACTS.md](../CONTRACTS.md) §2 |

## 배경 (왜 막혔는지)

원작 기본값은 25fps=40ms/프레임이며 현재 stub은 "1 프레임 = 1 틱"이지만, 참가자 봇이 40ms 안에
연산을 끝내기엔 타이트할 수 있다는 우려가 있었음.

## 결정

**`tickFrameGroupSize = 1`(원본 그대로 매 프레임)로 확정.** `gameLoop()`은 `deltaTime` 보정 없이
"호출 1번 = 프레임 1개 전진"하는 구조라([`main.js:156-158`](../../../src/resources/js/main.js#L156-L158))
계산이 40ms를 넘겨도 게임이 깨지거나 desync되지 않고 체감 fps만 잠깐 떨어짐 — "실시간 데드라인을
못 지키면 오류"인 시스템이 아님. 규칙 기반 로직(비교/분기 몇 개)은 마이크로초 단위라 40ms에 수백~수천
배 여유가 있고, 진짜 위험(무한루프로 메인 스레드가 멈추는 것)은 틱을 늘려도 해결되지 않으므로
[ADR-0002](ADR-0002-timeout-and-invalid-response.md)/[ADR-0003](ADR-0003-bot-execution-sandboxing.md)에서
다룸. 나중에 학습 기반 봇의 매틱 추론 비용이 실측으로 문제가 되면 그때 값을 올리는 쪽으로 재논의.
