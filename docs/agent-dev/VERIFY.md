# VERIFY.md — 커밋 전 로컬 검증 체크리스트

이 프로젝트는 **CI/CD를 두지 않기로 했습니다** (코드리뷰는 자동화 대신 정기 회의에서 대면으로).
그 대신, 커밋/PR을 회의에 들고 오기 전에 아래 5단계를 **로컬에서 직접** 실행하세요.
자동으로 걸러주는 장치가 없으니 이 체크리스트를 생략하면 그대로 회의 시간이 낭비됩니다.

## 체크리스트

### 1. Lint

```sh
npm run lint
```

`eslint:recommended` + prettier(`singleQuote`) 규칙 통과 확인.

### 2. Build

```sh
npm run build
```

webpack 프로덕션 빌드가 에러 없이 끝나는지 확인. (1+2를 한 번에: `npm run verify`)

### 3. 수동 스모크 테스트 (브라우저)

```sh
npx http-server dist
```

로컬 서버 접속(보통 `http://localhost:8080`) 후, **바꾼 부분과 관련된 시나리오를 최소 하나는
실제로 플레이해서 확인**하세요. 예:

- 입력 구조를 건드렸다면: 키보드 vs 키보드, 그리고 vs 기본 AI로 한 게임씩 정상 진행되는지.
- 테스트 환경을 건드렸다면: 에이전트 코드 로드 → 자기 키보드와 대결 → 기본 AI와 대결이 모두 되는지.
- 자동 테스트 스위트가 없으므로 이 단계를 건너뛰면 아무도 동작을 검증하지 않은 채로 회의에 오게 됩니다.

### 4. 계약 적합성 확인

바꾼 코드가 [CONTRACTS.md](CONTRACTS.md)의 **최신 버전**과 필드/의미가 일치하는지 스스로 diff
검토하세요. 만약 구현하다 보니 CONTRACTS.md와 다르게 가야 한다는 걸 발견했다면:

1. 코드를 먼저 확정하지 말고,
2. CONTRACTS.md를 갱신 + 버전을 올리고,
3. [DECISIONS.md](DECISIONS.md)에 왜 바뀌었는지 기록한 뒤,
4. 코드를 그에 맞게 마무리하세요.

### 5. 기록

[TRACKER.md](TRACKER.md)에 커밋 해시 + 한 줄 요약을 추가하세요. 이게 다음 정기 회의의
코드리뷰 안건이 됩니다 — 여기 안 적으면 회의에서 그 변경사항이 누락될 수 있습니다.

## 자동화하지 않는 이유

CI를 안 두기로 한 건 "돌아가는지"는 로컬에서 각자 확인하고, "이 방향이 맞는지"는 매번
사람이 모여서 판단하자는 결정입니다 ([AGENTS.md](../../AGENTS.md) §4). 이 체크리스트는 그 판단을
대체하지 않고, 회의 전에 최소한의 위생 상태를 보장하기 위한 것입니다.
